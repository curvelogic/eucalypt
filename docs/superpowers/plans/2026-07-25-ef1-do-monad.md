# EF1 — Combined effect monad (`do`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a single combined effect monad (working name `do`) that threads a
`{ state, seed }` context over IO, usable via `{ :do … }` block metadata, built
purely at prelude/library level with no runtime, driver or intrinsic change.

**Architecture:** A `do` action is a function `ctx → IO<{ value, ctx }>` where
`ctx = { state, seed }`. `do-bind` composes over the existing `io.bind`, letting
IO's world-token sequencing carry the context on its value channel. Three lift
functions adapt existing `io` / `state` / `random` actions into `do` actions; all
derived combinators come free from `monad(do)`. `do` lives in a new resource file
`lib/do.eu` that imports `resource:state` (mirroring how `state.eu` imports
`lens.eu`), so state's lens operators `=!` / `%!` reach `do`-block authors
transitively.

**Tech Stack:** eucalypt prelude/library code (`lib/*.eu`), Rust resource
registration (`src/driver/resources.rs`), the harness test framework
(`tests/harness/`).

## Global Constraints

- Both engines must agree byte-for-byte: every test runs under the default
  bytecode engine AND `EU_HEAPSYN=1`; outputs must be identical.
- Every regression test is fault-injection verified (break → FAIL → restore →
  PASS) and the PR body states this was done.
- Every `eu` invocation is wrapped `timeout 60 ./target/release/eu … --heap-limit-mib 12288`.
- GC soundness exercised under `EU_GC_VERIFY=2` (the suspended IO thunk carrying
  `{ state, seed }` must survive collection).
- `(.value)` IS a valid section (`x → x.value`); use it, do not avoid it.
- `io.map` argument order is `io.map(f, action)` — verified.
- `pair-ctx` uses distinct parameter names to dodge the `{x: x}` self-reference gotcha.
- UK English throughout. Gates before commit: `cargo fmt --all`,
  `cargo clippy --all-targets -- -D warnings`, `cargo test`.
- Modifying `lib/prelude.eu` requires regenerating `lib/prelude.blob`
  (`cargo xtask prelude-compile`); `lib/do.eu` and `lib/state.eu` compile from
  source and need no blob.

### Task 1: `lib/do.eu` — the `do` monad + register the resource

**Files:**
- Create: `lib/do.eu`
- Modify: `src/driver/resources.rs` (add `"do"` resource entry)

**Interfaces:**
- Consumes (from prelude, always in scope): `io.bind`, `io.return`, `io.map`,
  `io.shell`, `io.shell-with`, `io.exec`, `io.exec-with`, `random.float`,
  `random.int`, `random.choice`, `monad`; from `resource:state`: `state.get`,
  `state.put`, `state.modify`, `state.query`, `state.lift`, and operators `=!`/`%!`.
- Produces: a `do` namespace with `bind`, `return`, derived combinators (`map`,
  `then`, `and-then`, `join`, `sequence`, `map-m`, `filter-m`), members
  `shell`/`shell-with`/`exec`/`exec-with`/`get`/`put`/`modify`/`query`/`lift`/`st`/
  `float`/`int`/`choice`/`rnd`/`pure`/`lift-io`/`lift-state`/`lift-random`, and
  runners `run(a, c0)` / `eval(a, c0)`. `{ :do … }` block metadata registered in
  the same unit.

Reference spelling (from the proven spike prototype):

```
do-ret(v, c): io.return({ value: v, ctx: c })
resume(f, r): f(r.value)(r.ctx)
do-bind(m, f, c): io.bind(m(c), resume(f))

pair-ctx(c, v): { value: v, ctx: c }
do-lift-io(action, c): io.map(pair-ctx(c), action)
thread-state(c, s): { value: s.value, ctx: { state: s.state, seed: c.seed } }
do-lift-state(sa, c): io.return(thread-state(c, sa(c.state)))
thread-seed(c, r): { value: r.value, ctx: { state: c.state, seed: r.rest } }
do-lift-random(ra, c): io.return(thread-seed(c, ra(c.seed)))
```

Namespace:

```
` { monad: s"ctx → IO({value: a, ctx: ctx})" }
do: monad{bind: do-bind, return: do-ret} {
  shell(cm): do-lift-io(io.shell(cm))
  shell-with(opts, cm): do-lift-io(io.shell-with(opts, cm))
  exec(args): do-lift-io(io.exec(args))
  exec-with(opts, args): do-lift-io(io.exec-with(opts, args))
  get: do-lift-state(state.get)
  put(k, v): do-lift-state(state.put(k, v))
  modify(k, f): do-lift-state(state.modify(k, f))
  query(f): do-lift-state(state.query(f))
  lift(f): do-lift-state(state.lift(f))
  lift-state: do-lift-state
  st: do-lift-state
  float: do-lift-random(random.float)
  int(n): do-lift-random(random.int(n))
  choice(xs): do-lift-random(random.choice(xs))
  lift-random: do-lift-random
  rnd: do-lift-random
  lift-io: do-lift-io
  pure: do-ret
  run(a, c0): a(c0)
  eval(a, c0): io.map((.value), a(c0))
}
```

### Task 3: Gating harness test

**Files:**
- Create: `tests/harness/NNN_ef1_do_monad.eu` (pick the next free number)

**Interfaces:**
- Consumes `resource:do`. Computes `RESULT` from named checks per the gating
  convention (`docs/guide/testing.md`), following
  `tests/harness/189_r9oy_union_as_spec.eu` / `182_typedata_alias_resolution.eu`.

Checks to assert (deterministic — seed via `random.stream(<fixed>)`, no external IO):
- **all three effects in one `{ :do … }` block**: a state `put`/`modify`, a
  random draw, and a pure step; assert the returned value and the threaded final
  `state`.
- **parity**: the same state effect run through `state.run` directly, and the same
  random draw through `random.run` directly, produce the same values (proves
  delegation adds no drift).
- **runner shapes**: `do.run` yields `{ value, ctx }`; `do.eval` yields the value.

Keep IO out of the gating asserts (so the test needs no `--allow-io` gate); the
IO composition is already proven by the spike and exercised in Task 4's manual
GC run. If an IO step is included, mark the target `requires_io` and gate its run.
