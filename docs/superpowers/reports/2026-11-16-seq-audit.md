# `seq` audit of the prelude (eu-oaz72.161, owner decision 36)

`seq(a, b)` forces `a` to weak head normal form and returns `b` (a tail
call). This report lists prelude sites that grow the stack or build thunk
chains and that `seq` (directly, or through `foldl-strict`) would help. **None
of them is converted in the PR that adds `seq`**; this is the list for the owner.

## Method

Each "after" is the site rewritten as a user-level variant (`seq` or
`foldl-strict`) run on the release build with `eu -S`; "Max Stack" is the
reported machine stack depth, ticks are single runs (`measured-single`, not a
benchmark under `docs/superpowers/engine-ab/PROTOCOL.md`). n = 200,000 and the
list is `range(0, n)` unless stated. The stack figures are exact, deterministic
counts; the tick figures are indicative only.

## Findings

| # | Site | Max Stack before | after | Ticks before → after | Laziness / semantic change | Recommendation |
|---|------|-----------------|-------|----------------------|----------------------------|----------------|
| 1 | `max-of`, `min-of` (`foldl(max, l head, l tail)`) | 600,003 | 11 | 21.2M → 23.0M | `foldl-strict` evaluates `op(acc, x)` at each step; `max` is strict in both, so none for numbers. A non-scalar element ordered with `>` is forced only to the extent `>` forces it anyway. | **Convert** (to `foldl-strict`). Extends decision 31. |
| 2 | `reduce(op, l)` | 400,005 | 12 | 20.0M → 21.8M | `op(acc, x)` is evaluated even if `op` ignores its accumulator or element. | **Convert** if the owner accepts the strict contract of `foldl-strict`; otherwise document `reduce` as lazy and leave it. |
| 3 | `max-of-by`, `min-of-by` (and so `max-map`/`min-map` through `max-of`) | 1,000,002 | 13 | 26.2M → 28.2M | The accumulator is a `[x, v]` pair, so WHNF forces only the pair; each step's comparison forces `v` anyway. No change observed. | **Convert** (to `foldl-strict`). |
| 4 | `all-true?` (`foldl(and, true, l)`) | 400,008 | 15 | 29.0M → 30.8M | `and` short-circuits on a false accumulator, so later elements are still not forced. A non-boolean accumulator errors at the step rather than at the end. | **Convert** (to `foldl-strict`); `any-true?` is a `foldr` and is not in scope. |
| 5 | `range(b, e)` (`up(n): cons(n, up(n + 1))`, eu-pl9nn) | 400,002 on `nth(n - 1)`; also `last`, `foldl` | 14 | 20.4M → 22.0M (+8%) | `up(n)` becomes `seq(n, cons(n, up(n + 1)))`: the counter is forced as each cell is demanded, so a start that errors now errors at the first cell (before: when `e - b` is evaluated, which `__take` demands anyway). The comment on `range` records a ~10% cost on bench 022 and is why it was left on a lazy counter. | **Owner choice.** Stack fix is real (`range(0, n) last` is O(n) deep today) but costs ticks on a hot function; `iota` already gives the constant-stack form. Suggest converting and re-measuring bench 022 under PROTOCOL.md. |
| 6 | `iterate(f, i)` (`cons(i, iterate(f, f(i)))`) | 400,001 on `nth(n - 1)` | 9 | 11.6M → 13.2M | Forcing each element as its cell is demanded means an erroring or expensive `f` is applied when the cell is reached, not when the element is used. Observable for `iterate(f, x) take(k)` that never reads elements. | **Do not convert without owner decision** (semantic change). |
| 7 | `scanl(op, i, l)` | 400,008 on `last` | not measured | | Same shape as `iterate`: each accumulator is a thunk of `op`; forcing it changes when errors surface. | Same as 6: leave lazy. |
| 8 | `foldl` itself | 400,006 | n/a | | Deliberately lazy (`foldl(op, i, l)` may ignore its accumulator); it is the baseline against which `foldl-strict` is documented. | **Keep.** |
| 9 | `count`, `sum`, `product`, `iota` | 11 | 11 | | Already constant stack. | None. |
| 10 | `nth` | not growing | | | `i zero?` already forces the counter. | None. |

## Not stack growth

`last` (`head ∘ reverse`) was 400,003 deep on `range(0, n)` and 16 on
`iota(0) take(n)`: the depth is the `range` counter chain (item 5), not
`reverse`.

## Summary for the owner

Convert, no laziness concern: 1, 3, 4. Convert on a stated contract: 2.
Owner's call on tick cost: 5. Leave lazy unless the owner wants the semantic
change: 6, 7. Each conversion needs its own harness test and stack check; the
likely home is one follow-up PR on the prelude slot.
