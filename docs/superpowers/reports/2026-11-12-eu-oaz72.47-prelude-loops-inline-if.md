# eu-oaz72.47: prelude loops call the global `if` in blob mode

Date: 2026-11-12. Bead: eu-oaz72.47 (epic eu-oaz72).

## Finding

The defect is blob-only. In source mode the whole prelude goes through the
core inline pass, so `foldl`'s `if(l nil?, ...)` is already an inlined case.
`cargo xtask prelude-compile` skips that pass (to keep one form per binding)
and compiled with `suppress_inlining: true`, so the blob's `foldl` called the
global `if` (`⊗269`) with both branches thunked.

The O(n) stack in the bead title is not this defect. `foldl(+, 0)` at 1e6
reaches 2,000,004 frames in both modes, before and after: that is the lazy
accumulator chain (eu-oaz72.27). `foldl` with an operator that does not chain
its accumulator (`snd`) runs at max stack 10 before and after.

## Fix

Per binding, `xtask` runs the core inline pass over the body with the
prelude's bare intrinsic aliases (`if: __IF`, `nil?`, `head`, `=`, ...)
bound around it, then reopens the scope so anything left unreduced compiles
to its global as before, and compiles with intrinsic-wrapper inlining on.

Inlining every closed combinator (`then`, `//=`, `nth`, ...) as well was
tried: ~10% fewer ticks again, but it moved `errors/error_176`'s blob-mode
primary from the `//=` operator to the string literal, the hazard eu-oaz72.34
recorded, and grew the blob to 1086 KB. Alias-only avoids both.

## Measurements

Ticks are deterministic (same count on every run); max stack likewise.
`EU_PP_THRESHOLD=999999999`, release build, pre-decoded dispatch, one
x86_64 4-core container. Label: **measured-single** (one machine).

| program (n = 1e6) | blob before | blob after | source mode |
|---|---|---|---|
| `foldl(+, 0)` ticks | 154,250,168 | 128,250,158 | 107,750,094 |
| `foldl(+, 0)` max stack | 2,000,004 | 2,000,003 | 2,000,004 |
| `foldl(snd, 0)` ticks | 127,250,185 | 107,250,167 | 78,750,117 |
| `foldl(snd, 0)` max stack | 10 | 10 | 2,000,002 |
| `sum` ticks | 181,000,179 | 135,000,160 | 107,750,093 |
| `sum` max stack | 1,000,009 | 9 | 2,000,004 |
| `count` ticks | 167,000,178 | 131,000,158 | 86,750,105 |
| `count` max stack | 1,000,009 | 9 | 2,000,001 |

`sum` and `count` in blob mode lose their O(n) stack as a side effect.
Source mode still grows the stack O(n) for `sum`, `count` and
`foldl(snd)`: not addressed here.

The remaining gap to source mode is mostly source mode inlining `foldl` into
itself a few levels at the call site (visible in `eu dump stg`).

## Cost

Blob size 608 KB → 723 KB. A trivial program (`x: 1`) executes 231.7 M →
242.2 M instructions (+4.5%, callgrind, measured-single); the growth is in
the eager predecode of the larger bytecode in `BytecodeMachine::new`. The
all-combinator variant cost +20% here.
