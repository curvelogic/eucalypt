# eu-oaz72.34: constant-stack loops through `then` — root cause and measurements

Date: 2026-11-12. Baseline: master 362ef55. Change: branch
`eu-oaz72.34/constant-stack-loops`. Both binaries `cargo build --release`
with a freshly generated prelude blob, same machine, `EU_PP_THRESHOLD=999999999`.

## Root cause

The bead's hypothesis (IF branches allocated as thunks) does not hold on
master: a saturated `IF` is already inlined as `case c of True → …; False → …`
and the branch binding is a non-updatable value, so loop B already ran in
constant stack. The O(n) stack is in loops written through `then`:

1. Catenation makes `c then(t, f)` the curried `App(App(then, [t, f]), [c])`.
   `beta_reduce` only reduced an application whose own argument list
   saturates the lambda, so `then` was never reduced.
2. In blob mode `then` was not in the inlinable set at all: xtask's
   fixed-point tagged each candidate before substituting intrinsic aliases,
   so `if(c, t, f)` never looked like a closed body. Rounds after the first
   added only directly-closed lambdas.

Each iteration then entered the recursive call through an updatable thunk:
one stack frame per iteration.

The fix merges curried applications of closed-bodied inlinable combinators
(recursive combinators such as `map` excluded) and substitutes intrinsic
aliases before tagging in xtask. That adds `then`, `when`, `!`, `!=`, `//`,
`//=?`, `assert`, `second`, `¬` and `↑` to the blob's inlinable set, matching
the source path. A compile-time tail-position `IF` in the STG compiler was
prototyped and dropped: with the two fixes it changed no tick, allocation or
stack figure.

## Loops (1e6 iterations)

- A `lazy(i, a): if(i = 0, a, lazy(i - 1, a + 1))`
- B `if(a < 0 ∨ i = 0, a, f(i - 1, a + 1))` (strict accumulator)
- C `range(0, n) foldl(+, 0)`
- D A written with `then`
- E B written with `then`

Ticks, allocations and max stack are deterministic (**measured-verified**).
Wall is the median of 5 interleaved old/new runs, with min..max
(**measured-single**).

| loop | ticks/iter old → new | allocs/iter old → new | max stack old → new | wall median old → new (s) |
|---|---|---|---|---|
| A | 37 → 36 | 7 → 6 | 2,000,002 → 2,000,002 | 2.57 (2.45..2.67) → 2.54 (2.51..2.67) |
| B | 57 → 56 | 10 → 9 | 8 → 8 | 3.61 (3.51..3.62) → 3.56 (3.45..3.90) |
| C | 161 → 160 | 18 → 17 | 2,000,006 → 2,000,006 | 10.27 (9.72..10.85) → 10.26 (9.89..10.37) |
| D | 50 → 36 | 8 → 6 | 3,000,002 → 2,000,002 | 3.99 (3.72..4.12) → 2.55 (2.49..2.59) |
| E | 73 → 56 | 11 → 9 | 1,000,009 → 8 | 4.81 (4.72..4.91) → 3.59 (3.50..3.65) |

E at 3e6: Max Stack 8 (measured-verified). 1e7 could not be run here:
with no collections (eu-oaz72.4) the heap exceeds the 15 GB machine, and
under `--heap-limit-mib 2048` the run thrashes past 300 s.

## Not addressed

- A and D keep 2e6 stack: the lazy accumulator `a + 1` builds a thunk chain
  forced at the end (eu-oaz72.27).
- C (`foldl`) is unchanged: the prelude itself is compiled with
  `suppress_inlining` from un-inlined bodies, so prelude loops still call the
  global `if`. Follow-up bead.
